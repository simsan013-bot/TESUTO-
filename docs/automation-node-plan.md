# Node版自動化パイプライン 方針メモ

このメモは`apps/`配下のGAS実装（人間が手作業でも使う既存App群）に手を入れず、
**同じ成果物を出す自動化パイプラインをNode.jsで別途構築する**という決定の
経緯・方針をまとめたもの。セッションを分けても文脈が失われないようにする
ための記録。

## 経緯（なぜNode版が必要になったか）

`apps/producer`はGAS上で動く前提のオーケストレーターで、Sim確認ゲート・
チェッカー①〜⑤・音声/猫感想/画像工程までは実装済み（`apps/producer/README.md`
参照）。ただしGASはGoogleアカウントへのOAuthログイン（`clasp login`）を経て
初めて実行できる仕組みのため、Claude Codeのサンドボックス環境からは
実際に動かして検証することができない（Googleアカウント・clasp認証情報への
アクセス手段が存在しないため）。

検証・自動稼働をこの環境主導で行いたいという要望から、GASに依存しない
構成を別途用意する方針になった。

## 方針：ハイブリッド

- **`apps/`配下のGAS実装はそのまま維持**（人間が手作業で使う既存Appとしての
  役割を継続。今回の作業で変更しない）
- **新規ディレクトリ`automation-node/`にNode.jsの自動化パイプラインを構築**
  - 各GAS Appのプロンプト文面（`Prompts.gs`等）は一字一句そのまま移植する
    （成果物のクオリティに関わる部分は変えない、というこれまでの方針を継続）
  - 保存方式・オーケストレーション方式はGASに縛られず最適な形にする

## ストレージ方式（Excel/Word不採用の理由）

機械同士のデータ受け渡しにOffice形式は不要・不向き（パースが面倒、壊れやすい）
と判断し、以下に統一する：

| 用途 | GAS版 | Node版 |
|---|---|---|
| キュー・工程状態管理 | 自動化キューシート（Spreadsheet） | SQLite 1ファイル（`better-sqlite3`） |
| 工程間の台本受け渡し | Google Docs | プレーンテキスト（`.txt`） |
| 画像/音声/字幕の最終成果物 | Google Drive | ローカルファイル（png/wav/srt、形式は変更なし） |
| 人間が一覧で見たい場合 | スプレッドシートを直接閲覧 | SQLiteから読み取り専用CSVを書き出す（必須ではない、後回しでよい） |

## オーケストレーション方式

GAS版は producer ⇄ 各App を個別のWebアプリ（HTTP POST＋合言葉）として
分離しているが、これはGASがコンテナバインドのスクリプトプロジェクト単位で
しか動かせない制約に対応するための構造。Node版は1プロセス内で完結するため、
HTTP・合言葉のレイヤーは不要で、各工程はただの関数呼び出しにする。

`PIPELINE_EXECUTION_ORDER`・`PIPELINE_GATE_AFTER`・`PIPELINE_EXECUTORS`
（`apps/producer/Pipeline.gs`）に相当する工程順序・ゲート定義はそのまま
Node側の設計にも引き継ぐ（同じパイプライン構造、同じ工程名）。

## 常駐方法（本番運用時）

このチャットセッション自体は一時的なコンテナなので、開発中の動作確認は
ここで行えるが、24時間稼働させるには別途常駐先が必要。優先順：

1. **GitHub Actionsの定期実行（cron）**：サーバー契約不要、APIキーは
   GitHub Secretsで管理、GASの時間主導トリガーと同じ発想（一定間隔で
   1tick実行）。まずはここから。
2. **小規模VPS**＋cron/pm2：処理量が増えたら移行。
3. **サーバーレス**（Cloud Run + Cloud Scheduler等）：スケールが必要になったら検討。

大きい生成物（画像/音声）をGitHub Actions上で作る場合、リポジトリへの直接
コミットは避け、S3互換ストレージ（Cloudflare R2等）へのアップロードを想定。
検証フェーズの間はローカル/このセッション内で生成して都度確認すればよい。

## ディレクトリ構成（予定）

```
automation-node/
  package.json
  src/
    pipeline.js        # PIPELINE_EXECUTION_ORDER等、工程順序・ゲート定義
    stages/             # 各工程の実行関数（GAS版のExternalApps.gsに相当）
    prompts/            # 各App由来のプロンプト文面（無改修で移植）
    storage/            # SQLite・テキスト・ローカルファイルの読み書き
  data/                 # 実行時生成物（gitignore対象）
    queue.db
    works/{workId}/...
  .github/workflows/    # 定期実行用ワークフロー（後日追加）
```
